# Project: Consolation 0.1.0 — Changelog

This milestone brings together three months of work on the multiplayer client for *007: Quantum of Solace*. The product version is now **0.1.0**; revision numbers, Git hashes and Debug/nightly labels remain separate build metadata.

This is a development milestone, not a finished replacement for every original service or a declaration that every Xbox map is fully supported. The movement changes below are implemented in source but still require rebuilding and in-game verification. No project build or gameplay test was performed for this changelog.

## Player movement and input

### Reversible movement presets

`pm_movement_mode` accepts `stock` (the default) and `iw3`. The host/frontend applies the selected preset once when it changes, using the engine's setters. Individual server-replicated controls can still be tuned afterward; remote clients consume the host's values instead of expanding presets locally.

The experimental `iw3` preset enables sprint-to-ADS, keeps scoped ADS on damage, allows native prone clearance, disables cover, selects first-person mantle/climb cameras, and suppresses airborne movement bob. Switching to `stock` restores native sprint and damage policies, weapon-controlled prone permission, cover, third-person traversal cameras and normal bob. It does not reset unrelated jump-height or speed settings.

QoS already has the jump-step collision algorithm found in KisakCOD, including an 18-unit jump-step default. That native path is preserved rather than replaced with an unverified physics hook. Full COD4 ledge-strafing, mantle and ladder parity remains unverified; `iw3` is a configurable COD4-style preset, not a complete 1:1 movement port. Test `stock → iw3 → stock`, including transitions while in cover or traversal, before considering reversion validated.

### Sprint directly into ADS

`pm_adsStopsSprint 1` allows an ADS request to end sprint through the engine's own sprint-ending routine. Sprint input stays suppressed until the movement step has completed, so the later weapon update cannot immediately cancel the ADS request. This operates in the shared movement path rather than only the controller adapter.

Setting the server-replicated dvar to `0` restores the original behavior. Sprint timing and release bookkeeping remain native. The hook also uses the verified QoS ADS button bit rather than the previously incorrect declaration.

### Keep ADS when taking damage

`pm_adsExitOnDamage 0` suppresses the native scoped-ADS cancellation branch, including the per-player override that could otherwise re-enable it. Damage, recoil, flinch and script restrictions are not disabled. Setting it to `1` permits the original policy; it does not force every weapon to exit ADS when damaged.

This is a targeted change to the identified scoped-ADS path, not a claim that all possible weapon or animation interruptions have been removed.

### Native prone permission

`pm_allowProne 1` enables the surviving QoS prone permission, clearance and stance-transition path despite the weapon-level no-prone gate. This preserves native geometry checks rather than forcing a player into an invalid stance.

Setting it to `0` rejects new permission checks; `2` (the default and stock preset) restores native weapon permission. It does not forcibly stand an already-prone player or bypass ladder, script or clearance restrictions. Prone animation availability and multiplayer prediction still need gameplay verification.

### Cover toggle

`pm_allowCover 0` blocks the native cover-entry routine, including automatic and queued entry, and clears the cover-entry hint. When already in cover, the client begins the native forced-exit transition and lets the regular cover update perform its animation and cleanup.

The default is `1`, which retains native permission rules. This does not override stock `cover_disable`, turn cover into COD4 movement, or bypass script restrictions.

### First-person mantling and climbing

Two separate server-replicated camera options have been added:

- `pm_mantleFirstPerson 1`: use the first-person view branch for the native mantle-height traversals.
- `pm_climbFirstPerson 1`: use it for native ladders, ledges and pipes.

The patches suppress the traversal/external-model camera replacement while preserving the movement state, traversal timing and collision code. Setting either option to `0` restores the corresponding stock camera behavior. Explicit third-person requests, death/spectator views, balance traversals, generic transitions and wallhug are excluded.

These are **experimental camera implementations**, not a complete 1:1 port of COD4 mantle or ladder movement. They do not add COD4 first-person hand animations. Entry, exit, camera clearance and transitions need in-game testing.

### Airborne bob control

`pm_airborneBobScale` ranges from `0` to `1`, defaulting to `1` (stock amplitude); the `iw3` preset selects `0`. It scales the input to the native movement-camera bob helpers while airborne and outside traversal. This provides a targeted alternative to setting `bg_bobMax 0`, which also removes grounded bob.

Grounded bob, actual velocity, recoil, damage kick and landing effects remain unchanged. This is a mitigation for the reported airborne crouch/strafe problem; confirming that it resolves the excessive gun movement still requires reproducing that case.

### Native bindings and overhead names

The native `bind` command now accepts arbitrary console commands instead of restricting bindings to the stock action whitelist. Key parsing, command quoting, key-up behavior and configuration persistence stay with the engine.

Overhead names retain native visibility, team checks, positioning and distance scaling. `cg_overheadNamesFont` selects native, normal, big, small or bold fonts; `overheadFontNext` cycles them. Missing assets fall back to the native font. Existing `cg_overheadNamesSize` controls scale, with font selection occurring before native height normalization and text-width measurement.

Font selection now defaults to native and is cheat-protected. The cycling command also explicitly checks `sv_cheats`, since its internal setter otherwise bypasses console dvar protection. These debugging controls have been removed from the Commands page.

Noclip also has restored vertical jump/crouch input and a `pm_noclipScale` speed multiplier.

## Xbox fastfiles and the Canals milestone

The converter has advanced from collision-only and white-world probes to visible textured Canals geometry, sky and world rendering in reported gameplay. The separate Canals loading-screen material also rendered successfully.

The Canals file used throughout the early project was the **prototype alpha version**, not the final release map. Work is now moving to the original released Xbox Camille Pack files to produce a PC-compatible DLC package. That package is not yet declared complete.

Conversion work includes endian-safe asset names and material constants, PC-compatible collision and relocation, surface vertex streams, world/DPVS draw records and visibility storage, image decoding and mip-chain handling, lightmap metadata, and validated reuse of compatible PC material/technique assets.

Native runtime allocations and renderer-state diagnostics were added around previously failing world-load and draw paths. A fallback that avoids a crash is not treated as a final visual conversion.

The milestone flythrough is available in the [Fastfile Devlog](https://github.com/ProjectConsolation/Client/wiki/Fastfile-Devlog).

### Increased asset limits

Xbox zones put more pressure on the PC pools, exposing limits that were too small for the conversion work. The client increases these verified QoS pools:

| Asset | Stock QoS | Consolation |
| --- | ---: | ---: |
| FX | 340 | 600 |
| Image | 2,800 | 4,096 |
| Material | 1,626 | 4,096 |
| Stringtable | 5 | 80 |
| Weapon | 256 | 320 |
| Xmodel | 640 | 1,500 |

The renderer's sorted-material backing table was also expanded to prevent the larger pool from overwriting adjacent state. The native draw-surface material index remains 11 bits, so **2,048 simultaneously sorted materials** is still a separate rendering limit.

These changes do not increase the zone/hunk memory limit. World at War's T4M memory patches and its Loaded Sound pool were not blindly applied to QoS.

## Modding and asset overrides

### IWI, DDS and PNG image replacement

Loose images can override existing image assets from `consolation/images`. Supported formats are validated PC IWI, supported DDS formats and PNG. Selection uses image-asset names, with safe filename encoding where necessary, and preserves the original material's asset identity and sampler semantics.

Priority is PNG, then DDS, then IWI. An invalid preferred file retains the zone image rather than silently replacing it with another candidate. Overrides load when their owning image/zone is loaded; saving a file does not hot-reload its texture.

### IWD loading and image export

IWD image packaging is supported under `consolation/main`, allowing replacements to be distributed together instead of as hundreds of loose files.

The conversion tools can export decoded embedded Xbox images into PC-compatible IWI/DDS files and optional PNG previews. Dumps preserve image names and report shared images without embedded pixels rather than fabricating them. Normal maps must use the channel encoding expected by the PC shaders.

### GSC loading and the live-reload investigation

Disk-backed GSC overrides remain supported through the `consolation` script directory.

**Live GSC reload is currently disabled.** The experimental implementation retained compiler roots past native finalization and redirected VM code positions; its ownership assumptions were unsafe. Native script finalization and VM dispatch remain enabled. Script changes currently require a map restart.

A safe replacement still needs a VM-safe compiler transaction, recoverable failures, atomic publication, save debouncing and bytecode lifetime management for suspended/running threads. Live reload is not advertised as a working 0.1.0 feature.

### Scaleform and legacy menus

Loose Scaleform overrides and a legacy `.menu` loading path have been added. The new frontend uses an SM2-inspired horizontal navigation bar, play cards, logo treatment and animated map-preview backgrounds.

Menu work includes cropped previews, slow panning, crossfades, a transparent black video overlay, quit confirmation and handoff to existing QoS submenus. These changes remain under development: submenu return, Escape confirmation, focus, scaling and service-dependent screens need runtime verification. Existing Scaleform lobbies are not claimed to be fully replaced.

Scaleform font inspection/export tooling does not by itself establish a finished native in-game font import pipeline.

## Offline support and profiles

An optional local `xlive.dll` is included in the build packaging with a README explaining that it is intended for **offline/debug use**. Installing it is not a replacement for working Windows LIVE online services.

Offline work includes SDK-informed compatibility behavior, local identities linked to the engine name, persistent profile/settings infrastructure, local session bookkeeping, socket compatibility and launcher argument forwarding. Storage, session and matchmaking behavior remain development areas rather than a claim of complete online-service emulation.

Profile/config tools assist with configuration conversion, deduplication and locating the active profile.

## Console, HUD and diagnostics

Console work includes input/autocomplete fixes and ultrawide-related layout improvements. Full 1:1 COD4 console parity has not been established.

The blue version overlay, configurable positioning and watermark styling have been revised. HUD safe-area bounds were added without intentionally applying them to the Consolation version or watermark overlays; menu/loading-screen interactions still need regression testing.

`cg_drawMemInfo` provides a live memory overlay: a summary mode, expanded console-style values in MB, and expanded byte values. It includes working/private/peak/free information and warning colors. Material/technique diagnostics and asset-pool inspection provide more useful evidence when conversion fails.

Crash diagnostics, minidump preservation, renderer fallback logging, preload synchronization and cache-lifetime fixes have been developed to make failures easier to investigate.

## Miscellaneous fixes

The development period also includes controller and raw-input work, bot support, private-match/startup compatibility, launcher forwarding, branding/icon updates, build-generation and optional-offline packaging fixes, and numerous collision, asset-lifetime, rendering and shutdown corrections.

These fixes improve the foundation but do not guarantee that every historical crash, unsupported input path or external-service dependency is resolved.

## Verification and remaining work

The new movement patch sites were checked against the QoS PC IDA database and compared with KisakCOD where relevant. Patch installers validate expected instructions and warn/skip on mismatches. Source whitespace checks passed. These checks are not a substitute for compilation or gameplay tests.

Before treating movement as validated, test both toggle settings, keyboard/controller input, prone clearance, cover exit, each supported traversal type, crouch-strafe jumps, respawns and map changes. Multiplayer prediction requires matching patched clients and server settings.

Remaining release work includes:

- Runtime validation of the new movement/input/camera hooks and mixed-state transitions.
- Diagnosing residual Canals lighting/reflection issues and conversion fallbacks.
- Completing and testing all released Camille Pack zones, images, loading screens and map metadata.
- Regression testing shooting, effects, unloading, quitting and repeated map changes.
- Finishing the frontend/lobby workflow and native font-loading integration.
- Replacing unsafe live GSC reload with a verified design.
- Continuing offline/service compatibility and console/display regression tests.

0.1.0 marks substantial progress across three months of development, with visible Xbox-map rendering as a major milestone. It remains a development client with explicitly documented unfinished work.
